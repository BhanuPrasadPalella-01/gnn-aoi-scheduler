Which sensors should report right now?

A base station (the sink) watches many sensors but the radio channel only lets a few of them transmit in each time slot. Classic Age-of-Information scheduling simply asks the stalest sensors. But neighbouring sensors measure almost the same thing, so a fresh reading from one also tells the sink a lot about its neighbours. This project learns to exploit that.

1

Learn from history

From the training days the sink learns each sensor's typical daily pattern (heating cycles, rush hour), how fast each sensor drifts, and a correlation graph: which sensors move together.

2

Track what it doesn't know

A Kalman filter keeps an estimate of every sensor, including the silent ones, plus an uncertainty for each. Hearing from one sensor also shrinks the uncertainty of its correlated neighbours.

3

Decide with a GNN

A graph neural network reads the graph (age, uncertainty, drift speed, deadline per sensor) and picks sensors one at a time, each pick aware of the previous ones so it avoids redundant polls.

4

Never let anyone go stale

A hard freshness guarantee: any sensor that has been silent for too long is forced to report. Every scheduler obeys it, so the comparison is fair.

5

Learned by trial and error

The GNN starts as the classic model-based scheduler and is improved with reinforcement learning (PPO) on simulated networks and on historical real data, learning when to look ahead and when not to trust the model.
